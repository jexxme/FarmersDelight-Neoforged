Farmer's Delight Neoforged is vectorwing's Farmer's Delight ({meta.modVersion.split('+')[0]} content) ported to Minecraft 26.x on NeoForge. Gameplay, item ids and recipe ids are the same; this page lists what is not.

## What the port changes

Minecraft 26.x moved many things into data and components. The port follows:

- **Canvas Signs use the vanilla sign block entities.** Old `canvas_sign` and `hanging_canvas_sign` block entities are aliased to vanilla's, so existing signs load <Cite c={port.aliases} /> <Cite c={port.signEntities} />. The old `basket` id is aliased to `bamboo_basket` too.
- **Fuel, compost and villager food values are default item components** instead of data maps <Cite c={port.defaultComponents} />.
- **Villager trades are data files**, switched on and off by the trade config options through a load condition.
- **The common config is a local config** with the old file name <code>{configFiles.common.value}</code>, because NeoForge for 26.3 dropped the common type <Cite c={configFiles.common} />.
- **Tool-ability ingredients fall back to tool tags** for the vanilla abilities NeoForge removed <Cite c={itemAbility.fallbacks} />.
- **Drinks are built from consume effects** (`farmersdelight:remove_random_effects`, `farmersdelight:heal`, `farmersdelight:extinguish`).
- **REI support** is added on Minecraft 26.1.2 and newer, adapted from Farmer's Delight Refabricated. EMI and CraftTweaker are not available yet. See [Compatibility](/compatibility/).

## Behaviour that differs

These are how {meta.modVersion} behaves today. Each one is in the code as linked.

<dl class="fd-diffs">
<dt><Item id="minecraft:rabbit_stew" /> gives no Nourishment</dt>
<dd>With `enableRabbitStewBuff` on (default), Rabbit Stew gets {rabbit.nutrition} hunger and {+rabbit.saturation.toFixed(1)} saturation <Cite c={rabbitStewBuff} />, and the soup handler skips it, so the {duration(rabbitSoup.duration)} Nourishment listed for it is never applied <Cite c={rabbitStewSkip} />. Its tooltip still shows Nourishment. Turn the buff off to get the Nourishment with vanilla food values.</dd>

<dt><Item id="onion_soup" /> uses Shepherd's Pie values</dt>
<dd>It is registered with the Shepherd's Pie food values ({food('onion_soup').food.nutrition} hunger, {food('onion_soup').food.saturation} saturation) and {duration(nour('onion_soup'))} of Nourishment; the registration carries a "double check" note <Cite c={port.onionSoup} />.</dd>

<dt><Item id="chicken_soup" /> and <Item id="fried_rice" /> give {duration(nour('chicken_soup'))} of Nourishment</dt>
<dd>Farmer's Delight 1.3.2's changelog says both were moved down to the 3-minute tier; in this port they give {duration(nour('chicken_soup'))} and {duration(nour('fried_rice'))}.</dd>

<dt>A thrown <Item id="rotten_tomato" /> is a snowball</dt>
<dd>Thrown by a player, it flies as a vanilla snowball, with the rotten tomato sound <Cite c={port.rottenTomatoThrow} />. Fired from a dispenser it is the mod's own rotten tomato <Cite c={port.rottenTomatoDispense} />.</dd>

<dt>JEI shows the water dough recipe with two wheat</dt>
<dd>JEI's display <Cite c={jei.doughDisplay} /> differs from the recipe, which takes exactly one <Cite c={doughNeedsOne} />. JEI also has no info page for the <Item id="copper_knife" />; REI shows both correctly.</dd>

<dt>Some content is registered but unused</dt>
<dd>The tags `#farmersdelight:horse_feed_tempted` and `#farmersdelight:flint_tool_materials`, the loot function <code>farmersdelight:{port.smokerCook.value}</code> <Cite c={port.smokerCook} />, and the `farmersdelight:` biome whitelist and blacklist tags are not read by anything.</dd>
</dl>

<Aside title="Comfort">
Comfort is still registered but no food grants it. That is upstream's own change in 1.3.0, which moved those foods to Nourishment; see [Nourishment & Comfort](/mechanics/effects/).
</Aside>
