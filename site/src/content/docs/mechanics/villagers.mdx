Villagers know Farmer's Delight crops. Farmers buy them, the wandering trader sells seeds, villagers pick the crops up and plant them, and villages can generate with compost heaps and cabbage, tomato and onion plots.

<Shot src="mechanics/village-compost.jpg" caption="The plains compost pile, one of the houses villages can generate: organic compost and rich soil in a fenced pen beside a small shed." />

## Trades

Trades are data files added to the vanilla trade tags. Each group can be switched off in the config; both are on by default.

### Farmer

Farmers **buy** crops for emeralds (`enableFarmerFDTrades`: {String(cfg('enableFarmerFDTrades'))}):

## Farming villagers

Farmers handle Farmer's Delight crops like wheat.

- **Pick up** (`#minecraft:villager_picks_up`): <Chips ids={picks.filter((i) => i.startsWith('farmersdelight:'))} compact />
- **Plant** (`#minecraft:villager_plantable_seeds`): <Chips ids={plants.filter((i) => i.startsWith('farmersdelight:'))} compact /> Rice and rice panicles are picked up but not planted.
- **Food value** for villager breeding: {fdFood.map((i) => `${i.name} ${i.villagerFood}`).join(', ')} <Src {...cite(village.villagerFood)} />.
- **Compost** at a composter: farmers may compost <Item id="cabbage_seeds" /> and <Item id="tomato_seeds" /> <Src path="src/generated/resources/data/neoforge/data_maps/item/villager_compostables.json" label="villager_compostables.json" />.
- **Rich Soil Farmland** counts as farmland: farmers look for any farmland block as a work spot <Src {...cite(village.poi)} />, and it is in `#neoforge:villager_farmlands` <Chips tag="neoforge:villager_farmlands" compact />.

## Villages

### Compost heaps

While `generateVillageCompostHeaps` is {String(cfg('generateVillageCompostHeaps'))}, a small compost-pile building joins the house pool of each village type <Src {...cite(village.heaps)} />. It holds [Organic Compost](/mechanics/organic-compost/).

<tbody>

The share compares the added weight with the vanilla pool's total weight <Vanilla {...cite(vanillaHousePoolWeight)} />; each house slot of a village draws from that pool.

### Crops in village farms

While `generateFDCropsOnVillageFarms` is {String(cfg('generateFDCropsOnVillageFarms'))}, Farmer's Delight adds a rule processor to the vanilla farm processor lists <Src {...cite(village.farms)} />. It turns some wheat into young cabbages, tomatoes or onions (age 0).

<table>
<thead><tr><th>Farm</th><th>FD rules (input, chance, crop)</th>{fdCrops.map((c) => <th>{cropName[c]}</th>)}<th>Still wheat</th></tr></thead>
<tbody>
{farms.map((f) => (
	<tr>
		<td><code>{f.list}</code></td>
		<td>{village.farms.value[f.kind].rules.map(([i, p, o]) => `${i} ${pct(p, 0)} → ${o}`).join('; ')}</td>
		{fdCrops.map((c) => <td><span class="fd-val">{pct(f.odds[c] ?? 0)}</span></td>)}
		<td>{pct(f.odds.wheat ?? 0)}</td>
	</tr>
))}
</tbody>
</table>

The percentages are the share of a farm's wheat plots, worked out from the code. They are lower than the raw rule chances, and cabbages never appear in plains or taiga farms, because:

1. The vanilla farm processor runs first and already turns some wheat into carrots, potatoes, beetroots, melons or pumpkins (for example plains: {vanillaFarmRules.value.farm_plains.map(([, p, o]) => `${pct(p, 0)} ${o}`).join(', ')}).
2. Each rule processor seeds its random numbers from the block position <Vanilla {...cite(ruleProcessorSrc)} />, so the Farmer's Delight processor replays the **same** numbers the vanilla one used. A rule only draws a number when its input block matches, and the first rule that passes wins <Vanilla {...cite(randomMatchSrc)} />.
3. Wheat that survived the vanilla rule "wheat → carrots, 30%" had a first number of at least 0.3, so the Farmer's Delight rule "wheat → cabbage, 30%", which reads the same first number, can never pass on it.

<Aside type="note">
This table is computed from the processor code and the vanilla processor lists, treating the position-seeded numbers as evenly spread. It has not been counted in generated villages.
</Aside>

## Details

- The trade files carry a `farmersdelight:config_enabled` load condition on their config option, so the option decides whether the offer is loaded at all.
- "Reputation discount" is the `reputation_discount` field of the trade file, used by vanilla's reputation pricing.
