Wild crops and mushroom colonies are added to biomes by {worldgen.length} NeoForge biome modifiers in `data/farmersdelight/neoforge/biome_modifier/`. Each one adds a placed feature; the placed feature decides how often a patch appears and the configured feature decides what a patch looks like.
For what players see, read [Wild crops & worldgen](/mechanics/wild-crops/).

## The biome modifier type

`farmersdelight:add_features_by_filter` adds placed features to every biome in `allowed_biomes`, unless the biome is in `denied_biomes` or its base temperature is outside the limits <Cite c={bm.codec} /> <Cite c={bm.modify} />.

| Field | Type | Required | Effect |
|---|---|---|---|
| `allowed_biomes` | biome id, list of ids, or `#tag` | yes | biomes that get the features |
| `denied_biomes` | same | no | removed from the allowed set |
| `min_temperature` | float | no | skip biomes with a lower base temperature |
| `max_temperature` | float | no | skip biomes with a higher base temperature |
| `features` | placed feature id, list, or `#tag` | yes | what to add |
| `step` | generation step, e.g. `vegetal_decoration` | yes | when it generates |

## Features

Every placed patch ends with the placement filter `farmersdelight:biome_tag` <Cite c={bm.biomeTagFilter} />, which only lets a position through when its biome is in the given tag. The shipped patches all use `#minecraft:is_overworld`.

Two feature types are registered <Cite c={bm.features} />:

- `farmersdelight:in_order` runs a list of placed features at the same origin, in order (the crop first, then its companion plants) and succeeds if any of them placed something <Cite c={bm.inOrder} />.
- `farmersdelight:wild_rice` places wild rice in water <Cite c={bm.wildRice} />.

## Changing where wild crops grow

Put a file with the same path in a data pack: `data/farmersdelight/neoforge/biome_modifier/<name>.json`. It replaces the mod's file.

- **Different biomes:** copy the mod's file and edit `allowed_biomes`, `denied_biomes` or the temperatures.
- **Rarer or denser patches:** override the placed feature (`data/farmersdelight/worldgen/placed_feature/patch_<name>.json`) and change the `rarity_filter` chance or the `count`.
- **No generation at all:** keep the modifier but give it an empty biome list.

<Code lang="json" title="data/farmersdelight/neoforge/biome_modifier/wild_carrots.json (in your data pack)" code={JSON.stringify({ type: 'farmersdelight:add_features_by_filter', allowed_biomes: [], features: 'farmersdelight:patch_wild_carrots', step: 'vegetal_decoration' }, null, 2)} />

<Aside type="caution" title="The farmersdelight biome tags do nothing">
The mod ships {fdBiomeTags.length} biome tags such as `#farmersdelight:wild_carrots_whitelist` and `#farmersdelight:has_wild_cabbage`. No biome modifier, feature or code refers to them; the modifiers use `c:` and `minecraft:` tags directly. Editing them changes nothing. Edit the biome modifier instead. Their contents are on [Tags](/pack-makers/tags/#tags-worldgen).
</Aside>

<Aside type="note" title="Not tested in game">
The empty-list override has not been tested in game for these docs. Chunks that already exist keep their plants; changes show up in newly generated chunks.
</Aside>
